O Problema da Ambiguidade

Quando um computador lê uma expressão matemática como 2 + 3 * 4, ele precisa decidir a ordem das operações. Sem regras estritas, o resultado pode ser catastrófico.

O Lexer (Analisador Léxico)

Antes de calcular, o ply quebra o texto em "tijolos" chamados Tokens. Ele não entende matemática, apenas identifica padrões.

INPUT: "10 + 2"

OUTPUT: [
  Token(type='NUMBER', value=10),
  Token(type='PLUS', value='+'),
  Token(type='NUMBER', value=2)
]
2

O Parser (Analisador Sintático)

O Parser recebe os tokens e tenta encaixá-los em regras gramaticais. Ele usa o algoritmo LALR(1), que significa que ele lê da esquerda para a direita e olha 1 token à frente (Look-Ahead).

  • ✓ Usa uma Pilha (Stack) para guardar o que já leu.
  • ✓ Decide entre SHIFT (Empilhar) ou REDUCE (Resolver).

O Segredo: Tabela de Precedência

Para resolver conflitos, definimos "pesos" para os operadores. No código Python, isso é uma tupla. Visualmente, podemos imaginar como níveis de hierarquia. Quanto mais alto, maior a prioridade de resolução (binding power).

Código Python (PLY)

precedence = (
    ('left', 'PLUS', 'MINUS'),
    ('left', 'TIMES', 'DIVIDE'),
)

A ordem importa! O que está em baixo na lista tem maior prioridade.

Regra de Ouro

Se o token atual na pilha tem precedência MENOR que o token que está vindo (Look-Ahead), o parser faz SHIFT (espera).

Conclusão

  • Parsers LALR(1) são eficientes: Eles tomam decisões complexas olhando apenas um passo à frente, evitando backtracking custoso.

  • Precedência é Chave: A configuração correta da tupla de precedência no ply elimina a necessidade de gramáticas excessivamente aninhadas.

  • Resultado Garantido: Com a configuração correta, 2 + 3 * 4 será sempre 14.

Receba a Inteligência

O Parser prefere Shift (esperar) quando o próximo operador é mais forte, e Reduce (resolver) quando o próximo é mais fraco ou igual.
